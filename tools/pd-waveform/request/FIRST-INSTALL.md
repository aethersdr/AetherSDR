# Independent first installation (development)

The ARM64 development path passed clean installation, reboot persistence and
receive-only local DAX IQ qualification on a FLEX-8600 running 4.3.16.42034.
Installation used ordinary public waveform uploads, without an installed shim
credential or diagnostics bridge as its installation transport. This is a bench
qualification of the development candidate, not production or FLEX-6000 approval.

## Authorization and identity

The operator approves a `PDFST001` plan bound to the radio serial, firmware,
signed release digest, new admin-token SHA256, hostname and random installation
ID. The publisher key is compiled into the native requester, delivery adapter and
worker. Artifact assembly does not grant consent. The qualification uploader
requires the exact plan digest through `--approve-plan`; it is a development
client, not a shipping catalogue or desktop credential-management flow.

The first-install waveform contains public inputs only. Its shell entry uses
`exec` to start the fixed native requester and has an empty setup section. It
contains no bearer token, transport key, configurable commands or arbitrary
installer path. The new bearer token remains in a private client file during
qualification. Production desktop integration must store it in the credential
vault and bind its reference to this attempt.

`pd-first-request` runs as UID 78666/GID 20 with no capabilities and NoNewPrivs.
It verifies the release, worker, plan and live radio identity, snapshots inputs
into unlinked RAM files, and generates a transport secret in RAM. A bounded
Unix broker grants that private descriptor once to each of two UID-0 roles:
accept and deliver. Incoming ancillary descriptors and repeated roles are
rejected. The carrier's public `PDFPUB01` record binds the worker and plan to
this attempt's nonce.

Unlike the installed-shim upgrade protocol, this path has no predecessor token
or published commitment to a secret generated by that predecessor. The initial
operator-approved public waveform upload is its authority boundary. A process
already running as the waveform UID can race or deny service, or invoke the
same exact approved job; it cannot replace the pinned plan or signed worker.
Do not represent this as stronger isolation between applications sharing that
UID. The normal waveform upload facility itself remains a privileged firmware
installation interface.

## Transaction and runtime

The explicit fresh plan is different from `PDMIG001`. A missing predecessor
never converts a migration into a fresh installation. First installation checks
that the legacy container is absent and refuses an unrelated installed store.
It stages and verifies the signed release, publishes its protected intent and
recovery capsule, then initializes a new private `provision.json` atomically.
Only the token hash is persisted. No prior identity files are copied.

The new identity starts in `local` state with an installation ID and authenticated
LAN control. It does not join a tailnet or create a Tailscale identity. Tailnet
sign-in is a separate operator action. The shim and AetherPD run as the ordinary
waveform user; fixed root boot/session adapters retain only their existing
bounded jobs. Removing the temporary carrier does not remove those fixed
adapters, because they are required at boot and for IQ session setup.

The worker verifies the running executable, selected payload and local identity
before committing. `first-selection` binds that selected payload record to the
plan. After commitment and cleanup, a root-owned RAM `PDVIEWF1` record allows
`GET /v1/aetherpd/installation` to report `first_install_plan_blake2b_256`, the
selected release and publisher key. The endpoint requires the new bearer token.
Delivery success and ordinary HTTP readiness are not commitment.

Interrupted installation uses the existing independent recovery service.
Recovery disables the new runtime and preserves the owned identity; it never
reconstructs an absent predecessor. Interrupted preparation may resume only
when its protected intent matches. A different attempt cannot adopt that store.
A terminal failed installation needs an explicit owned-store recovery/removal
workflow before a new attempt; this client does not silently erase it.

## Qualification procedure

1. Obtain exclusive bench access. Confirm the
   current radio/firmware and receive state. Do not transmit.
2. Rebuild and verify the current candidate and record all artifact digests.
3. Preserve the old store, private identity and systemd units in a protected,
   recoverable backup. Remove them from the active paths and prove that the
   shim listener and old runtime are absent. Bench diagnostics may prepare this
   fixture, but may not deliver or authorize the new installer.
4. Use `run_first_install.py` with the exact reviewed plan digest. It uploads the
   public native waveform and per-attempt carrier through the normal radio API,
   then verifies authenticated commitment and the new identity. It uses no old
   shim credential, SSH or diagnostics bridge for installation.
5. Remove both temporary waveforms and independently audit capsule, installer
   process, broker, carrier/container and cached-artifact cleanup. Public
   uninstall acknowledgement alone does not prove cached files were deleted.
6. Reboot once. Verify a changed boot ID, the same new identity/token, an exact
   matching committed record, automatic startup and an unprivileged primary.
7. Start a bounded receive-only AetherPD session with FDX disabled. Prove local
   DAX IQ packet delivery and cleanup of the fixed ARP/capture resources. No RF
   correction claim follows from this receive-only test.
8. Save evidence and restore the protected old installation if qualification
   fails. Actual FLEX-6000 installation and Linux 2.6 behavior remain separate
   hardware gates; this initial requester supports ARM64 only.

## Recorded FLEX-8600 result

Evidence and build scripts are under `fresh-install-implementation` in the
persistent evidence root recorded by `../PROGRESS.json`.

- `attempt-04/radio-install.json`: public native requester and container carrier
  installed the exact approved plan and initialized a new local identity.
  The predecessor store, units and standalone container were preserved separately
  before testing. Bench root diagnostics prepared that fixture and audited it;
  they did not deliver or authorize the installation.
- `reboot-validation.json`: one reboot changed the boot ID, and the same identity
  and committed plan returned automatically after 44.187 seconds. The original
  `reboot-result.json` remains a failed raw report because its immediate SSH
  boot-ID read preceded diagnostics availability. The subsequent host audit
  supplies the missing boot-ID evidence; no second reboot was needed.
- `receive-iq-result.json`: with FDX disabled, the installed AetherPD process
  supplied 16,384 complex IQ samples at 48 kHz, centered on 7.150 MHz. All
  32,768 float components were finite and 30,252 were nonzero. Capture covered
  about 341 ms. No RF commands were sent; keyed and correcting remained false.
- `post-reboot-audit-result.json`: the surviving primary ran as UID 78666 with
  all capability sets zero and NoNewPrivs enabled. Session workers, fixed ARP,
  private bootstrap sockets, temporary installer/recovery units and carrier
  containers were absent; `accept_local` remained zero. Fixed runtime boot and
  session adapters remain installed for their bounded jobs.
- `cached-artifact-cleanup-result.json`: failed-attempt retained upload files
  were removed after exact hash checks. Successful temporary uploads were
  removed through the proper firmware removal commands. Protected predecessor
  backups remain available; they are not part of the new identity.
- `backup-audit-result.json` and `stop-backup-result.json`: the preserved legacy
  standalone shim container restarted under its original `always` policy after
  reboot. It was stopped again; its identity hash is unchanged. The new runtime
  was verified independently by executable hash, UID, new bearer token and
  committed plan. The backup container policy remains unchanged, so another
  reboot can restart it until backup retirement is resolved. This bench-fixture
  limitation is not a clean absence-of-predecessor proof after reboot.

built from native source at `7c87bc223`. The approved plan BLAKE2b-256 is

The release uses a development publisher key.

## Firmware upload contract

Native packages use `file filename <name>.ssdr_waveform` followed by
`file upload <size> new_waveform`, and removal uses `waveform uninstall`.
Container archives use `file upload <size> waveform_docker_image <name>.tar.gz`
and `waveform remove_container`. They do not use the native upload route.
The native basename is alphanumeric: this firmware strips hyphenated prefixes
from legacy upload names, which prevents the matching archive directory from
starting. These commands agree with the existing WaveformInstaller and FlexLib
paths and were exercised on the bench.

The native requester does not register a DSP waveform, so public waveform
inventory is not its readiness signal. The authenticated handoff and exact
committed plan establish success. Optional `client program` labeling was refused
by this firmware in the receive proof; omitting that label allowed normal GUI
registration and IQ capture.

## Remaining gates

Production desktop consent and credential-vault integration, publisher catalogue,
installation interruption qualification and the actual FLEX-6000 adapter/hardware
remain open. A local identity does not prove Tailscale enrollment persistence.
This receive-only result does not qualify RF correction, sustained performance,
stock APD comparison, or the rest of the production completion plan.
